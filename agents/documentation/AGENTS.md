# Documentation contribution assignment

This guide applies to an actual specialist assignment. The root developer may write tightly coupled tests and small documentation updates directly; no handoff is required solely by file type.

This supports the [root developer](../../AGENTS.md) when preparing a documentation issue and reviewing its worker contribution. Current source uses `agent:documentation`: writer, protected checks, frozen source and draft publication, without an embedded model reviewer or fabricated verdict. Documentation schema-4 post-publication repair is rejected. Verify the sealed installation supports the selected route; Generalist is retired in source.

- Describe the implemented behavior, intended readers, exact documentation files, affected examples and acceptance criteria. Link the relevant code and current implementation commit.
- Include the parent PR number and delivery branch. Free-form issues may leave exact documentation scope/checks for preparation: the operator must select `--target-pr NUMBER`, then current-source admission uses verified `ready` and one matching role label without `blocked` (older sealed installations may require digest approval). Legacy envelopes instead set numeric `pull_request` and supply verified scope/checks. Follow the [route-specific guidance](../../docs/agent-setup/free-form-issues.md); a PR link alone does not select delivery.
- Document observed supported behavior. Distinguish planned capabilities, local source, installed releases, passing checks and live delivery. Update examples and relative links after moves or removals.
- Keep application code and runtime policies outside the documentation assignment. Report inconsistencies to the root developer.
- Deliver onto the latest parent PR branch, preserve other contributions, and report the commit SHA, changed sections and actual verification. The root developer checks the final prose against the implementation. Run this handoff when its inputs are stable and conflicting work has released the PR reservation.
